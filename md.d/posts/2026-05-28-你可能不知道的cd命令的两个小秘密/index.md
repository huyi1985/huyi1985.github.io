# 你可能不知道的cd命令的两个小秘密


在 Unix V0 的源代码中，可以看到一个名为 `chcom` 的标签，大致相当于现代编程语言中的常量，它的值是`<ch>`——不妨理解为现代编程语言中的 `"ch"`。

```asm
// https://github.com/DoctorWkt/pdp7-unix/blob/master/src/cmd/sh.s#L411  
  
chcom: <ch>
```

`chcom` 很可能是 “**CH**ange directory **COM**mand” 的缩写。

cd 的前世今生：一条命令的四十年漂移
  
  如果你在 Linux 上输入 type cd，会看到：cd is a shell builtin。一个人人都会的命令，居然没有对应的可执行文件？这背后藏着一段跨越四十年的命名史。

  第一章：它本来叫 ch
  
  1969 年，PDP-7 机器上跑着世界上第一个 Unix。那台机器只有 8K 字的内存，Ken Thompson 写的 shell
  也极其简陋——整个解释器不过几百行汇编，现在还能在 pdp7-unix 项目中读到原始代码。

  Shell 在识别内建命令时，比较的是用户输入的前两个字符。切换目录的命令，存在一个叫 chcom 的标签里：

```
  " src/cmd/sh.s, line 411
  chcom: <ch>
```
  
  `<ch>` 是 PDP-7 汇编的字符打包语法，表示把字母 c 和 h 压进一个18位字里。识别逻辑也只有四行：

```
  lac args       " 取命令名的前两个字符
  sad chcom      " 是 'ch' 吗？
  lac args+1
  sad spsp       " 后面是空格？（命令只有两个字符）
  jmp doch       " 是的，执行 chdir
```

所以，Unix 诞生之初，切换目录的命令是 ch，不是 cd，也不是 chdir。

到了Unix V1，找到sh中chdir的实现

Dennis Ritchie（DMR）后来曾被问及这段历史，表示自己也记不清当年为何从 ch 扩展成了 chdir——那段代码太早了，细节已经模糊。

到了BSD bill joy
  
内核里的系统调用从一开始就叫 chdir，编号 17，从未改过名字。pdp7-unix 和 unix-history-repo
  两个项目里的内核代码（s2.s）几乎一字不差：

```
  " src/sys/s2.s, line 197
  .chdir:
     jms argname    " 解析路径名
     jms iget       " 读取 inode
     lac i.flags
     and o20        " 检查目录标志位
     sna
     jms error      " 不是目录：报错
     lac ii
     dac u.cdir     " 把 i-number 写入进程的"当前目录"字段
     jmp okexit
```

  就这九行。chdir 系统调用做的事情只有两件：确认目标是个目录，然后更新进程的 u.cdir 字段。

  于是出现了一个有趣的割裂：内核叫 chdir，shell 叫 ch。用户输入的是 shell 命令，shell
  内部再去调用系统调用，两个名字可以完全不同。

  ---
  第三章：中间短暂存在过的 chdir
  
  稍晚一些，有人基于 Unix V1 的 shell 风格写了另一个 shell（pbsh.s），这次内建命令跟着内核走，也叫 chdir：

```
  " src/other/pbsh.s, line 474
  chdirstr:
     <ch>;<di>;<r 040     " 'c','h','d','i','r',' ' — 即字符串 "chdir"
```

  识别的时候三个字一起比：

```
  lac argv0
  sad chdirstr      " 前两字符 'ch'？
  lac argv0+1
  sad chdirstr+1    " 再比 'di'？
  lac argv0+2
  sad chdirstr+2    " 再比 'r '？
  jmp changedir     " 全部匹配，执行
```
  所以在 PDP-7 时代，ch 和 chdir 都曾是"切换目录"的合法命令，取决于你用的是哪个 shell。

  ---
  第四章：Bill Joy 把它改成了 cd
  
  时间来到 1976 年。加州大学伯克利分校的 Bill Joy 在修改 Unix shell 时，留下了一段注释（后来被引用在 BSD sh.c
  的文件头里）：

```
  /*
   * UC berkeley shell
   *
   * Modified by Bill Joy Oct 14, 1976
   *
   *  cd for "chdir"          ← 在这里
   *  interruptible waits
   *  ...
   */
```

  cd for "chdir"——就是这一行。Joy 把命令名从 chdir 缩写成了 cd，理由不得而知，也许只是顺手。就这样，cd 成了标准，沿用至今。


## 秘密2：cd 为什么不是一个可执行文件

  今天在任何 Linux 上运行：

  $ type cd
  cd is a shell builtin

  /bin/ 里找不到 cd，/usr/bin/ 里也没有。这不是疏漏，而是物理上不可能做到。

类比函数形参不能改变实参数

  原因在于 chdir() 系统调用的本质：它只改变调用者自身的当前目录。

  如果 cd 是一个独立的可执行文件，shell 运行它时会 fork() 出一个子进程，子进程调用 chdir()，成功切换目录，然后 exit()
  退出。但父进程（也就是 shell 本身）的当前目录，一分一毫都不会变。

  这是进程隔离的基本规则：子进程的任何状态变更，都不会反向影响父进程。

  因此，cd 必须是 shell 的内建命令，由 shell 进程直接调用 chdir() 系统调用，才能真正改变你的位置。这个约束在 1969
  年成立，在 2026 年同样成立。


  四十多年，一条命令走过了三个名字：ch → chdir → cd。内核里的系统调用编号 17 始终叫
  chdir，连实现都没变过几行。用户界面的命令名却反复漂移，最终在 Bill Joy 的随手一改后定格。

  所以，cd 是 Unix 历史上一个相当罕见的案例：它的内核实现只有九行汇编，永远不会有对应的可执行文件，而且它的名字是由三个不同
  的人在不同年代分别决定的——最终叫什么，大概不是任何人深思熟虑的结果。
