# C++ 26新容器性能如何？hive会取代vector和list吗？

C++ 26 将加入一个新的标准容器 hive，以兼顾 vector 高效访问的优点和 list 灵活修改的能力，在遍历性能、内存效率和操作成本之间寻找更好的平衡。

vector 最大的优势是速度，元素连续存储，CPU 缓存命中率高，编译器还可以进行 SIMD 优化。但插入和删除操作会导致大量元素移动是其明显的缺点。

list 则采用完全不同的设计。通过链表节点保存元素，插入和删除操作简单，但每个元素都需要额外的指针开销；遍历时需要频繁访问分散的内存空间，导致缓存效率较低。

hive 则综合二者的特点，采用了一种折中的设计。它由多个独立的内存块组成，但块内部的存储单元又是连续的，就像蜂巢内的“房间”一样。hive 还为每个内存块维护着一个“记账本”，用来记录和跳过已删除的位置。删除元素时只需标记空位，无需移动其他元素。

性能测试显示，在插入数据时，hive 的速度约为 vector 的一半，但比 list 快近一个数量级。遍历数据时，hive 与 list 性能接近，但因为无法充分利用连续内存带来的优势，明显慢于 vector。

真正体现 hive 价值的是删除场景。在随机删除大量元素时，它比 list 快出几十倍；相比 vector，在频繁删除的场景下可以避免大量数据搬移。

在内存占用方面，hive 只略高于 vector ，而 list 则需要额外消耗数倍的空间，以管理链表节点和指针。

总之，hive 并不是一个更快的 vector，而是一种介于数组和链表之间的新型容器。它适用于那些既需要较好遍历性能，又存在大量动态创建和删除对象的程序。
