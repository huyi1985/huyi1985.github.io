# JSON 竟是被那种交友网站带火的

今天，JSON 是最为广泛使用的数据格式之一，既可用于系统间的数据传输，又可用于数据的存储，甚至可以作为配置文件的格式。

能否正确输出 JSON 以至成为了衡量 AI 是否足够“智能”的标准。几代人不断努力的目标明明是让 AI 使用自然语言与人类交流，现在却不得不强迫 AI 返回结构严谨的数据。

![](img1.png)
> 在 DevDay 大会上，ChatGPT 第一次拥抱 JSON

时光倒回到 2001 年，JSON 之父 Douglas Crockford 发现了一种比 XML 更加精简的数据格式——不是发明——JSON。 当他兴致勃勃地向客户介绍 JSON 时，竟被客户以”JSON 不符合标准，我们不能用“的理由拒绝了。

![](img2.png)

Douglas 也是思路清奇，既没有设法说服客户，也没有向各种组织和委员会递交资料，好为 JSON 争取个名分。而是购买了 json.org 这个域名，建立了一个网站。说是网站，其实里面就只有一个对 JSON 进行介绍的网页，仅此而已。

“好了，现在 JSON 是一个标准了！”，Douglas 自言自语道。

![](img3.png)

随着时间的流逝，Douglas 这种”自欺欺人“的做法竟然生效了，人们渐渐发现了 JSON 的价值——JSON 的确比 XML 容易多了，好用就行，还管它标不标准呢。

> 今天 JSON 确实是项标准了。
> 
> 2006 年，IETF 通过 RFC 4627 对 JSON 首次进行了标准化。2013 年秋， Ecma International 又通过 ECMA-404 将 JSON 正式标准化。随后，RFC 8259 于 2017 年发布，是 Internet Standard STD 90 的当前版本。同年，JSON 又被标准化为 ISO/IEC 21778:2017。

风向的变化是如此之快，时间来到 2009 年圣诞节前夕，Douglas 突然收到了来自网站托管服务（虚拟主机服务）公司的电子邮件，被告知由于他的 json.org 使用了太多带宽，因此要支付更多的费用。

“到底发生了什么？json.org 怎么突然就火了？”Douglas 随即查看了网站的日志。原来是一个叫作 onlinebootycall.com 的网站在源源不断地下载 `json.org/json.js` 这个文件。

为什么要下载这个文件呢？原来，那时的浏览器还没有内置对 JSON 的支持，要想使用 JSON 传输数据，就必须引入 Douglas 编写的 `json.js` 这个文件中的代码。

onlinebootycall.com 乍看之下像是在线聊天网站，但英语中的 booty call 可不是普通的电话。当小伙伴晚上突然打电话给你，约你去他/她家看个电影什么的……online booty call 往好听了说是在线交友，实际上就是……

JSON 在当时显然不是主流的数据格式，可见是什么在驱动技术的进步。

Douglas 觉得凭什么你们一夜风流过后让我为带宽买单呢，尽管 JSON 似乎也一夜成名了。

而且这样也不安全啊，这里说的是从远程服务器加载程序脚本的安全隐患。至于其他安全问题，一介程序员的 Douglas 也无能为力吧。于是，Douglas 决定出手阻止这种行为，以一种他自认为**不会伤害任何人的方式**来提醒其他程序员，不要从远程服务器轻易加载程序脚本。

但他的做法再次反映出不同常人的思路，说是提醒，实际上看起来更像是发起了一次针对 onlinebootycall.com 的网络攻击。Douglas在 `json.js` 的开头加了这样一行代码！

`alert('IMPORTANT: Remove this line from json.js before deployment.');`

好了，现在每个去 onlinebootycall.com “交友”的人都看能到这句警告，还是在一个错误对话框中。

![](img4.png)

网站负责人不得不悬崖勒马，紧急把 `json.js` 保存到了自己的服务器上，但就不知道有没有浇灭网站用户交友的热情了。
