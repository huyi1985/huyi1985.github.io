# 女朋友的一句担心，让他在凌晨重写了51万行代码，走到了法律边缘

2026 年 3 月 31 日，完整的 Claude Code 源代码意外泄露，导致超过 51 万行代码在几小时内被迅速传播。整个开发者社区陷入疯狂。

![构建时默认生成的.map 文件中包含了源代码](/assets/06pd9f.webp)

> @Fried_rice 被认为是最早报告该源代码泄露事件的用户，其相关推文的发布时间为 08:23 UTC。

大约 1 小时后，名为 @realsigridjin 的用户在凌晨 4 点（09:18 UTC，他应该在美国中部），被手机不断涌来的通知惊醒——AI 社区已经因为泄露事件彻底沸腾。他迅速在 GitHub 上创建了一个备份仓库，将相关代码进行归档保存。

![@realsigridjin 迅速在 GitHub 上创建了一个备份仓库](/assets/h9gt15.webp)

Anthropic 发现旗下产品的源代码被泄露，迅速启动应对机制，依据 DMCA takedown（美国《数字千年版权法》下的版权移除机制）向 GitHub 等平台发出删除请求。

DMCA takedown 的核心机制是：当版权方发现其受保护内容被未经授权公开时，可向平台提交正式通知，要求依法下架相关内容；平台在确认后通常会迅速移除或限制访问，以规避潜在的法律责任。

随后，GitHub 上多个或是直接上传，或是镜像 Claude Code 源码的代码仓库被相继删除、设为私有或限制访问。

到目前为止，事态似乎得到了控制。但来自 @realsigridjin 女朋友的担忧，让形势发生了戏剧性变化。

## “我女朋友真的很担心”

“当时女朋友真的很担心。她觉得只是把代码存放在电脑里，也可能会被原作者追究法律责任。” @realsigridjin 回忆道，“于是，我做了**任何工程师都会做的事**：坐下来，从零开始把核心功能用 Python 重新实现了一遍，并**在天亮之前**发布了复刻版。”

![UTC+8 8:11 PM 是美国中部时间的 7:11 AM，天刚刚亮](/assets/yp28t4.webp)

在这短短的 3 个小时内，@realsigridjin 仅仅是借助 AI 工具（oh-my-codex）就完成了从零复刻 50 多万行 TypeScript 代码的工作。功能一致，结构高度相似，但代码表达完全不同。新的仓库发布后**仅 2 小时即突破 5 万星标，创下 GitHub 传播速度的纪录**。

能在凌晨 4 点爬起来的 @realsigridjin 是一家 AI 初创公司从业者，曾在 2025 年独自使用了 250 亿个 token。他在复刻版的 README 文件中展现出他的“野心”：“Better Harness Tools, not merely storing the archive of leaked Claw Code”（我们要做更好的工具，而不仅仅是归档泄露出的源代码）。

![@realsigridjin 的“野心”](/assets/mkfqq8.webp)

随后，该项目还宣布启动 Rust 重写分支，目标是打造“更快、更安全”的运行时。这场源代码泄露风波仿佛成了一个意外的产品发布前奏。

## 法律上踩线，技术上高效，伦理上争议

事情能发展至此，关键在于一个古老但在 AI 时代愈发微妙的法律原则：**著作权保护的是“表达”，而非“思想”**。

换句话说，你不能复制代码，但可以用另一种编程语言实现同样的功能。如果一个系统被另一种语言“重新表达”，那么可能不再构成直接侵权。问题在于，这条边界在实践中极其模糊——尤其当 AI 可以在几小时内完成“理解 + 重写”的全过程时。

从法律角度看，这正是一个典型的灰色地带。一方面，原始代码显然受版权保护，DMCA 删除合理且必要；另一方面，重写版本是否属于“独立实现”，还是“变相复制”，则取决于实现过程的细节：是否参考了原代码？结构是否高度相似？是否存在“实质性相似性”？这些问题往往需要漫长的法律审查，而不是一次简单的删除请求就能解决。想想 Oracle 与 Google 那起围绕 Java API 的诉讼案，前前后后历时了 11 年。

这起事件似乎传递出一个信号：在 AI 的加持下，“源代码泄露 → 快速重构复刻 → 再发布”正在变成一种可复制的流程。过去需要团队和时间完成的逆向工程，现在可以被压缩到一个通宵；过去难以触及的实现细节，如今可以通过模型推理快速还原。闭源代码仍然受到法律保护，但它在技术层面的“不可复制性”正在被削弱。

当 AI 可以轻易重现代码的“思想”，而法律只保护“表达”，那么软件版权的边界，究竟还剩下多少？
